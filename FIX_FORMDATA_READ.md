# Исправление проблемы с чтением FormData

## Проблема

Разрыв соединения происходит до начала обработки - при чтении `request.formData()`. Локально работает, на сервере нет.

## Возможные причины

1. **Лимит размера body в Next.js** - по умолчанию 1MB для API routes
2. **Таймаут на чтение request body** - большой файл читается слишком долго
3. **Проблема с памятью** - файл не помещается в память при чтении
4. **Проблема с nginx буферизацией** - хотя мы отключили `proxy_buffering off`

## Решения

### Решение 1: Проверить что nginx конфигурация применена

```bash
# Проверьте что proxy_buffering off установлен
sudo grep -A 5 "location /" /etc/nginx/sites-available/nodejs.conf | grep buffering

# Должно быть: proxy_buffering off;
```

### Решение 2: Попробовать маленький файл

Попробуйте загрузить файл размером 1-2MB. Если работает - проблема в размере.

### Решение 3: Проверить память

```bash
# Проверьте доступную память
free -h

# Проверьте использование памяти приложением
sudo -u nodejs pm2 monit
```

### Решение 4: Проверить логи с новым логированием

После обновления кода проверьте логи:

```bash
sudo -u nodejs pm2 logs yana_app --lines 0 | grep TRANSCRIBE
```

Должны появиться логи:
- `[TRANSCRIBE] POST request received`
- `[TRANSCRIBE] Request method: POST`
- `[TRANSCRIBE] Reading FormData...`

Если логи обрываются на `Reading FormData...` - проблема в чтении FormData.

### Решение 5: Альтернативный подход - сохранить файл на диск

Если проблема в чтении FormData в память, можно попробовать сохранить файл на диск сначала, затем обработать. Но это требует изменения архитектуры.

## Проверка

1. Обновите код на сервере
2. Перезапустите приложение
3. Попробуйте загрузить файл
4. Проверьте логи - на каком этапе происходит разрыв

## Если ничего не помогает

Попробуйте использовать другой подход:
- Загружать файл частями (chunked upload)
- Использовать прямую загрузку в S3/объектное хранилище
- Использовать отдельный endpoint для загрузки файла, затем обрабатывать
