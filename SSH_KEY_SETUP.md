# Настройка SSH ключа для деплоя

## Вариант 1: Генерация SSH ключа (Рекомендуется)

### Шаг 1: Генерация SSH ключа на вашем компьютере

Откройте терминал и выполните:

```bash
# Генерация нового SSH ключа
ssh-keygen -t rsa -b 4096 -C "github-deploy-yana-app"

# Когда спросит, где сохранить ключ, нажмите Enter (по умолчанию ~/.ssh/id_rsa)
# Или укажите другое имя, например: ~/.ssh/yana_app_deploy

# Когда спросит пароль (passphrase), можете оставить пустым или установить пароль
```

После выполнения у вас будет:
- **Приватный ключ**: `~/.ssh/id_rsa` (или указанное вами имя)
- **Публичный ключ**: `~/.ssh/id_rsa.pub` (или указанное вами имя + .pub)

### Шаг 2: Добавление публичного ключа на сервер

#### Способ 2.1: Через ssh-copy-id (самый простой)

```bash
# Замените user на вашего пользователя (root, beget и т.д.)
# Замените your-vps-ip на IP вашего сервера
ssh-copy-id -i ~/.ssh/id_rsa.pub user@your-vps-ip

# Введите пароль, когда попросит
```

#### Способ 2.2: Вручную

```bash
# 1. Скопируйте содержимое публичного ключа
cat ~/.ssh/id_rsa.pub

# 2. Подключитесь к серверу по SSH с паролем
ssh user@your-vps-ip

# 3. На сервере создайте директорию .ssh (если её нет)
mkdir -p ~/.ssh
chmod 700 ~/.ssh

# 4. Добавьте публичный ключ в authorized_keys
nano ~/.ssh/authorized_keys
# Вставьте скопированный публичный ключ, сохраните (Ctrl+O, Enter, Ctrl+X)

# 5. Установите правильные права
chmod 600 ~/.ssh/authorized_keys

# 6. Выйдите из сервера
exit
```

### Шаг 3: Проверка подключения без пароля

```bash
# Попробуйте подключиться - теперь не должно спрашивать пароль
ssh user@your-vps-ip
```

### Шаг 4: Добавление приватного ключа в GitHub Secrets

1. Скопируйте содержимое **приватного** ключа:
   ```bash
   cat ~/.ssh/id_rsa
   # Или если использовали другое имя:
   cat ~/.ssh/yana_app_deploy
   ```

2. Перейдите в GitHub: `Settings → Secrets and variables → Actions`

3. Создайте новый секрет:
   - **Name**: `VPS_SSH_KEY`
   - **Value**: Вставьте весь текст приватного ключа (включая `-----BEGIN OPENSSH PRIVATE KEY-----` и `-----END OPENSSH PRIVATE KEY-----`)

## Проверка текущего SSH ключа

Если у вас уже есть SSH ключ, проверьте:

```bash
# Посмотреть существующие ключи
ls -la ~/.ssh/

# Если есть id_rsa.pub, можно использовать его
cat ~/.ssh/id_rsa.pub
```

## Решение проблем

### Проблема: "Permission denied (publickey)"

**Решение:**
1. Проверьте, что публичный ключ добавлен в `~/.ssh/authorized_keys` на сервере
2. Проверьте права доступа:
   ```bash
   chmod 700 ~/.ssh
   chmod 600 ~/.ssh/authorized_keys
   ```
3. Проверьте, что SSH сервер разрешает авторизацию по ключам:
   ```bash
   # На сервере
   sudo nano /etc/ssh/sshd_config
   # Убедитесь, что есть:
   # PubkeyAuthentication yes
   # AuthorizedKeysFile .ssh/authorized_keys
   # Затем перезапустите SSH:
   sudo systemctl restart sshd
   ```

### Проблема: "Host key verification failed"

**Решение:**
```bash
# Удалите старый ключ хоста
ssh-keygen -R your-vps-ip

# Или добавьте в known_hosts вручную
ssh-keyscan -H your-vps-ip >> ~/.ssh/known_hosts
```

## Безопасность

✅ **Рекомендуется:**
- Использовать SSH ключи вместо паролей
- Использовать пароль для SSH ключа (passphrase)
- Регулярно менять ключи
- Использовать разные ключи для разных серверов

❌ **Не рекомендуется:**
- Использовать один ключ для всех серверов
- Хранить приватные ключи в открытом доступе
- Использовать слабые ключи (меньше 2048 бит)
