# Исправление проблемы с загрузкой больших файлов

## Проблема

Для больших файлов (75MB) `request.formData()` зависает на сервере, хотя локально работает. После извлечения аудио размер уменьшается в 10 раз, но проблема в том, что Next.js пытается прочитать весь файл в память ДО извлечения аудио.

## Что сделано

1. **Увеличен таймаут для чтения FormData** - до 30 минут для файлов больше 50MB
2. **Увеличена память Node.js** - с 6GB до 8GB в `ecosystem.config.js`
3. **Добавлено логирование** - для отслеживания процесса чтения

## Проверка

После обновления кода:

```bash
cd /var/www/yana_app
git pull origin main
npm run build
sudo -u nodejs pm2 restart yana_app
```

Проверьте логи при загрузке большого файла:

```bash
sudo -u nodejs pm2 logs yana_app --lines 0
```

Должны увидеть:
- `[TRANSCRIBE] File size: XX.XX MB, timeout: 1800 seconds`
- `[TRANSCRIBE] Starting request.formData()...`
- `[TRANSCRIBE] FormData read successfully` (если работает)

## Если проблема сохраняется

### Вариант 1: Проверить память

```bash
# Проверьте доступную память
free -h

# Если памяти мало, может потребоваться увеличить swap
```

### Вариант 2: Проверить что nginx не буферизует

```bash
# Проверьте что proxy_buffering off
sudo grep -A 10 "location /" /etc/nginx/sites-available/nodejs.conf | grep buffering
```

### Вариант 3: Альтернативный подход

Если проблема в том, что Next.js не может обработать такой большой FormData, можно:
1. Разбивать файл на части на клиенте
2. Использовать прямую загрузку в S3/объектное хранилище
3. Использовать отдельный endpoint для загрузки файла, затем обрабатывать

Но сначала попробуйте с увеличенными таймаутами и памятью.
