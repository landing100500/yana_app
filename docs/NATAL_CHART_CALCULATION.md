# Расчёт натальной карты (Джйотиш)

Документация по технологиям, библиотекам и нюансам расчёта натальной карты в сервисе. Результаты сверяются с эталоном [vedic-horo.ru](https://vedic-horo.ru) и совпадают в пределах допустимых расхождений (секунды дуги).

---

## 1. Стек и библиотеки

| Компонент | Технология |
|-----------|------------|
| **Эфемериды и сидерика** | [Swiss Ephemeris](https://www.astro.com/swisseph/) через npm-пакет **`swisseph`** (v0.5.17) |
| **Часовой пояс на дату рождения** | **`geo-tz`** (IANA по координатам) + **`moment-timezone`** (оффсет на конкретную дату) |
| **Геокодинг** | Внутренний сервис геокодинга (`lib/geocoding.ts`) — координаты и часовой пояс по названию города |
| **Среда выполнения** | Node.js, расчёт выполняется только на сервере (динамический `require('swisseph')` в API) |

Swiss Ephemeris даёт тропические позиции планет и домов; сидерический зодиак получается вычитанием аянамши (см. ниже).

---

## 2. Цепочка расчёта

1. **Вход**: дата, время и город рождения из анкеты (местное время).
2. **Геокодинг**: по названию города получаем широту, долготу и базовый часовой пояс.
3. **Исторический часовой пояс**: для данной точки и **даты рождения** вычисляется реальный оффсет (UTC) через `getHistoricalTimezoneOffset()` (`lib/historical-timezone.ts`), чтобы учесть изменение границ поясов в прошлом.
4. **UTC**: местное время переводится в UTC по этому оффсету (включая корректный переход через полночь при смене дня).
5. **Юлианский день**: `swe_julday(year, month, day, utc_hour + utc_minute/60, SE_GREG_CAL)`.
6. **Расчёт карты**: по юлианскому дню и координатам считаются планеты, дома, асцендент, навамша, накшатры (см. разделы ниже).

Опционально в `.env` можно включить **местное среднее время (LMT)** для места рождения:  
`NATAL_CHART_USE_LMT=true` — тогда оффсет считается как `долгота/15` (без учёта административных границ). По умолчанию не используется.

---

## 3. Аянамша (сидерический зодиак)

- По умолчанию используется **Лахири** (`NATAL_CHART_AYANAMSA` не задан или `LAHIRI`).
- Режим задаётся **до** любых вызовов расчёта планет/домов: `swe_set_sid_mode(ayanamsa, 0, 0)`.

Доступные значения в `.env` (регистр не важен):

- `LAHIRI` (по умолчанию)
- `FAGAN_BRADLEY`
- `RAMAN`, `KRISHNAMURTI`, `YUKTESHWAR`, `USHASHASHI`
- `DELUCE`, `TRUE_CITRA`, `SS_CITRA`, `SURYASIDDHANTA`
- `SS_REVATI`, `TRUE_REVATI`, `TRUE_PUSHYA`, `TRUE_MULA`, `ARYABHATA`

Полный список режимов — в [Swiss Ephemeris](https://www.astro.com/swisseph/swephprg.htm#_Toc505244846). Результаты сверялись с vedic-horo при **Лахири**; для других сервисов можно подобрать режим через скрипт `scripts/test-ayanamsa-modes.ts`.

---

## 4. Дома и асцендент (Лагна)

- **Цель**: получить сидерическую долготу асцендента (Лагны) и MC. Дома в интерфейсе строятся по системе **Whole Sign** (каждый дом = целый знак от Лагны).
- **Источник позиций**: `swe_houses(tjd_ut, lat, lon, hsys)` — возвращает **тропические** куспиды и ascmc (в т.ч. асцендент и MC).
- **Системы домов**: используются только для получения асцендента/MC. Перебираются по порядку до первой успешной:
  - при **|широта| > 66.5°** (полярные области): сначала **E** (Equal), затем P, S, K, R;
  - при обычных широтах: **P** (Placidus), затем S, K, E, R.

На высоких широтах Placidus в Swiss Ephemeris может не сходиться; Equal даёт стабильный результат (например, для Норильска).

- **Перевод в сидерику**: после `swe_houses` асцендент и MC переводятся в сидерические долготы:
  - `ayanamsa = swe_get_ayanamsa(julianDay)` (уже с учётом выбранного режима);
  - `sidereal_longitude = (tropical_longitude - ayanamsa + 360) % 360`.
- Широта **не ограничивается** (используются фактические координаты места рождения).

---

## 5. Планеты

- Расчёт: `swe_calc_ut(julianDay, planetId, flags)` с флагами:
  - `SEFLG_SWIEPH` — использовать встроенные эфемериды;
  - `SEFLG_SPEED` — нужна для ретроградности;
  - `SEFLG_SIDEREAL` — позиции сразу в сидерическом зодиаке (с учётом текущей аянамши, заданной через `swe_set_sid_mode`).

Учитываются: Солнце, Луна, Меркурий, Венера, Марс, Юпитер, Сатурн, Уран, Нептун, Плутон, узлы (Rahu/Ketu через `SE_TRUE_NODE`). Караки (Атмакарака и др.) считаются по сидерическим долготам семи классических планет.

---

## 6. Навамша (D9)

- Каждый знак делится на 9 равных частей по **3°20'** (30/9 градуса).
- Номер части (1–9) в знаке: `floor(градус_в_знаке / (30/9)) + 1`.
- Знак навамши зависит от типа раши:
  - **Подвижные** (Овен, Рак, Весы, Козерог): 1-я навамша = тот же знак, далее по порядку.
  - **Фиксированные** (Телец, Лев, Скорпион, Водолей): отсчёт с 9-го знака от раши (например, с Козерога).
  - **Двойственные** (Близнецы, Дева, Стрелец, Рыбы): отсчёт с 4-го знака вперёд так, чтобы **9-я навамша совпадала с раши** (совместимо с vedic-horo и распространённой практикой Джйотиш).

Градус внутри навамши: остаток от деления градуса в знаке на размер одной навамши, умноженный на 9.

---

## 7. Накшатры

- **27 накшатр**, равные участки по **13°20'** (360/27), начиная с 0° Овна сидерического.
- Индекс накшатры: `floor(долгота / (360/27))`; пада (1–4): по четвертям внутри накшатры.
- Порядок имён соответствует стандартному (Ашвини → Ревати), включая **Пурнавасу** на 7-й позиции, чтобы границы Читра/Свати и др. совпадали с общепринятыми.

Управители накшатр: Кету, Венера, Солнце, Луна, Марс, Раху, Юпитер, Сатурн, Меркурий — по циклу от Ашвини.

---

## 8. Отображение в таблице

- В колонке **«Градусы»** выводятся **градусы в знаке** (0°–30°), а не полная долгота 0–360°, в формате градусы°минуты'секунды" (как на vedic-horo).
- Раши — сидерический знак по долготе (русские названия: Овен, Телец, …, Рыбы).
- Навамша и накшатра (с падой и управителем) считаются по тем же сидерическим долготам.

Небольшие расхождения в секундах дуги с другими сервисами допустимы из‑за различий в эфемеридах, округлении и точности времени/координат.

## 9. Переменные окружения

| Переменная | Значение по умолчанию | Описание |
|------------|------------------------|----------|
| `NATAL_CHART_AYANAMSA` | `LAHIRI` | Режим аянамши (Lahiri, Fagan-Bradley, Raman и др.). |
| `NATAL_CHART_USE_LMT` | не задано | Если `true`, для перевода времени в UTC используется местное среднее время (LMT) по долготе. |

---

## 10. Проверка расчёта

- Эталон: [vedic-horo.ru](https://vedic-horo.ru); при тех же данных (место, дата, местное время) и Лахири строки таблицы (Раши, Навамша, Накшатра) совпадают; возможны отличия в секундах градуса.
- Для перебора режимов аянамши по тестовому кейсу (например, Норильск, 25.07.1979, 14:00):
  ```bash
  npx tsx scripts/test-ayanamsa-modes.ts
  ```
  Скрипт выводит сидерический асцендент для каждого встроенного режима Swiss Ephemeris и подсказывает значение для `NATAL_CHART_AYANAMSA`.
