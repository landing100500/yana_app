# Быстрый старт: Использование пароля для деплоя

Если у вас есть только логин и пароль от VPS, вы можете использовать их для деплоя.

⚠️ **Важно**: Использование пароля менее безопасно, чем SSH ключ. Рекомендуется позже настроить SSH ключ (см. `SSH_KEY_SETUP.md`).

---

## Шаг 1: Настройка GitHub Secrets

Перейдите в `Settings → Secrets and variables → Actions` вашего репозитория GitHub.

Добавьте следующие секреты:

1. **VPS_HOST** 
   - Значение: IP адрес или домен вашего VPS
   - Пример: `123.45.67.89` или `your-domain.com`

2. **VPS_USER**
   - Значение: ваш логин от VPS
   - Обычно: `root` или `beget` (зависит от настроек Beget)

3. **VPS_PASSWORD**
   - Значение: ваш пароль от VPS
   - ⚠️ Введите пароль точно, как он есть (с учетом регистра)

4. **VPS_DEPLOY_PATH** (опционально)
   - Значение: путь к проекту на сервере
   - По умолчанию: `/var/www/yana_app`

5. **VPS_SSH_PORT** (опционально)
   - Значение: порт SSH
   - По умолчанию: `22`

---

## Шаг 2: Обновление workflow файла

Откройте файл `.github/workflows/deploy.yml` и найдите строки:

```yaml
# Вариант 1: SSH ключ (рекомендуется, более безопасно)
key: ${{ secrets.VPS_SSH_KEY }}

# Вариант 2: Пароль (менее безопасно, но проще для начала)
# password: ${{ secrets.VPS_PASSWORD }}
```

**Измените на:**

```yaml
# Вариант 1: SSH ключ (рекомендуется, более безопасно)
# key: ${{ secrets.VPS_SSH_KEY }}

# Вариант 2: Пароль (менее безопасно, но проще для начала)
password: ${{ secrets.VPS_PASSWORD }}
```

То есть:
- Закомментируйте строку с `key:`
- Раскомментируйте строку с `password:`

---

## Шаг 3: Проверка

После настройки:

1. Сделайте коммит и push изменений:
   ```bash
   git add .github/workflows/deploy.yml
   git commit -m "Configure password-based deployment"
   git push origin main
   ```

2. Перейдите в `Actions` в GitHub и проверьте, что workflow запустился

3. Если всё настроено правильно, деплой должен пройти успешно

---

## Переход на SSH ключ (рекомендуется)

После того, как всё заработает, рекомендуется настроить SSH ключ для большей безопасности:

1. См. инструкцию в `SSH_KEY_SETUP.md`
2. После настройки ключа вернитесь к использованию `key` вместо `password` в workflow

---

## Решение проблем

### Проблема: "Authentication failed"

**Возможные причины:**
- Неверный пароль
- Неверный логин
- SSH сервер не разрешает авторизацию по паролю

**Решение:**
1. Проверьте правильность пароля (скопируйте-вставьте, чтобы избежать опечаток)
2. Проверьте логин (обычно `root` или `beget`)
3. Попробуйте подключиться вручную:
   ```bash
   ssh user@your-vps-ip
   ```
   Если не получается, значит проблема с доступом, а не с GitHub Actions

### Проблема: "Connection refused"

**Решение:**
- Проверьте, что порт SSH открыт (обычно 22)
- Проверьте, что сервер доступен: `ping your-vps-ip`
- Проверьте файрвол на сервере
