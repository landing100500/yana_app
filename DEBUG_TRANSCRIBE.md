# Отладка проблемы с транскрибацией

## Проблема

`upstream prematurely closed connection while reading upstream` - Next.js закрывает соединение до завершения обработки.

## Диагностика

### 1. Проверьте появляются ли логи с префиксом [TRANSCRIBE]

```bash
sudo -u nodejs pm2 logs yana_app --lines 0 | grep TRANSCRIBE
```

Если логов нет - разрыв происходит до начала обработки (на этапе чтения FormData).

### 2. Проверьте размер файла и доступную память

```bash
# Проверьте доступную память
free -h

# Проверьте использование памяти приложением
sudo -u nodejs pm2 monit
```

### 3. Попробуйте маленький файл

Попробуйте загрузить очень маленький файл (1-2MB) - если работает, проблема в размере.

### 4. Проверьте логи nginx в реальном времени

```bash
sudo tail -f /var/log/nginx/error.log
```

## Возможные решения

### Решение 1: Увеличить память для Node.js

В `ecosystem.config.js` уже установлено `NODE_OPTIONS: '--max-old-space-size=6144'` (6GB).

Проверьте что это действительно применяется:

```bash
sudo -u nodejs pm2 show yana_app | grep NODE_OPTIONS
```

### Решение 2: Проверить что файл не слишком большой

Попробуйте файл размером 10-20MB сначала, затем увеличивайте.

### Решение 3: Проверить что FormData читается полностью

Если логи показывают `[TRANSCRIBE] Reading FormData...` но не показывают `[TRANSCRIBE] FormData read successfully`, значит проблема в чтении FormData.

### Решение 4: Временное решение - использовать прямой доступ к файлу

Если проблема в чтении через FormData, можно попробовать сохранить файл на диск сначала, затем обработать.

## Следующие шаги

1. Обновите код на сервере
2. Перезапустите приложение
3. Попробуйте загрузить файл
4. Проверьте логи - на каком этапе происходит разрыв
5. Пришлите логи для анализа
